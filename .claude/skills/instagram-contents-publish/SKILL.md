# instagram-contents-publish

`gen` 테이블의 신규 콘텐츠를 **gen 1건당 인스타그램 단일 이미지 게시물** 1개로 발행한다. (카러셀 아님, 카테고리 그룹핑 없음)

## 필요한 MCP
- **MySQL MCP** (`mcp__mcp_server_mysql__mysql_query`) — 조회 / 플래그 UPDATE
- **Aside MCP** (`mcp__aside__repl`) — instagram.com 브라우저 자동화 (사용자가 이미 로그인되어 있다고 가정). 7단계에서는 동일 MCP로 네이버 블로그(blog.naver.com) 자동화에도 사용한다 (역시 로그인되어 있다고 가정).

## 전체 절차

### 1. 대상 gen 조회 (MySQL MCP)
```sql
SELECT id, headline, summary, thumbnail_image_url, created_at
FROM gen
WHERE created_at >= CURDATE() - INTERVAL 1 DAY
  AND (published_via_skills_yn IS NULL OR published_via_skills_yn <> 'Y')
  AND contents_type = {프롬프트에서 제안한 값}
ORDER BY created_at;
```
- `{프롬프트에서 제안한 값}` 은 이 스킬을 호출한 프롬프트(또는 호출 스킬, 예: investing-dot-com-crawling)가 지정한 `contentsType` 값으로 치환한다. 값이 명시되지 않으면 사용자에게 확인한다.
- **gen 1건 = 인스타그램 게시물 1개.** 카테고리별 그룹핑은 하지 않는다.
- 대상이 0건이면 아무것도 하지 않고 종료 보고.
- 이후 2~7단계를 **gen 1건마다 순회**하며 수행한다. 한 건의 발행이 완전히 끝난 뒤 다음 건으로 넘어간다.

### 2. 카드뉴스 메인 이미지 생성 (HTML 템플릿 사용)
gen 1건에 대해 **이미지 1장**만 만든다. (상세페이지 이미지 없음)

#### 이미지 규격 (고정 — 반드시 준수)
- **카드 이미지는 정확히 `1440 x 1800 px` (가로:세로 = 4:5) 로 고정 생성한다.**
- HTML 템플릿의 최상위 `div` 는 `810 x 1012.5 px` (동일한 4:5) 이므로, 렌더 시 **`deviceScaleFactor` 를 `1.7778` (= 1440/810) 로 설정**해 캡처하거나, 뷰포트/클립 영역을 `810x1012.5` 로 고정한 뒤 결과를 `1440x1800` 로 리사이즈한다. 어느 방법이든 **최종 산출물은 정확히 1440x1800 이어야 한다.**
- 저장 직후 파일의 실제 픽셀 크기를 확인(`sips -g pixelWidth -g pixelHeight` 또는 이미지 메타)해 `1440x1800` 이 아니면 **이 gen은 업로드하지 말고 중단·보고**한다.

1. 현재 skills.MD가 위치한 디렉토리 하위에 html_templates 디렉토리가 있고, 여기 하위에 메인 카드 이미지에 대한 html 템플릿 파일(`main페이지.html`)이 있음.
2. 이 템플릿 1개만 사용한다. (상세페이지 템플릿은 더 이상 사용하지 않음)

#### main페이지 채우기
- **배경 이미지**: 이 gen의 `thumbnail_image_url` 이 있으면 그 값을 배경으로. null이면 템플릿 기본 배경 유지. HTML 템플릿 main페이지.html 파일의 thumnail_image.png 부분에 들어갈 이미지가 됨.
  - `thumbnail_image_url` 이 `http://` 또는 `https://` 로 시작하는 **원격 URL**이면 기존과 동일하게 Aside로 접속해 로컬에 다운로드한 뒤 사용한다.
  - `thumbnail_image_url` 이 **이미 로컬 절대경로**(`/` 또는 `~`로 시작하고 원격 스킴이 아닌 파일 경로 — 예: investing-dot-com-crawling 스킬이 만든 contents_type 4/5 건)이면, 다운로드 단계 없이 **해당 경로의 파일을 그대로** 배경 이미지로 사용한다. 이 경우 이 파일은 다른 스킬(크롤링 스킬)이 소유·정리하는 파일이므로 4단계 발행 성공 후 임의로 삭제하지 않는다 — 7단계에서 삭제 대상은 여전히 "2단계에서 만든 렌더링용 임시 디렉토리"뿐이다.
- **배경 이미지 디자인 검수 및 대체**: 확보한 `thumbnail_image_url` 이미지(원격 다운로드본이든 로컬 경로 파일이든)를 배경에 넣기 전에 실제로 열어 카드뉴스 배경으로 적합한지 확인한다.
  - 다음과 같은 경우 "디자인이 이상함"으로 판단한다: 워터마크·로고·자막 등이 크게 박혀있음, 화면 캡처/스크린샷/UI 이미지처럼 카드뉴스 배경에 부적절함, 해상도가 낮아 확대 시 깨져 보임, 이미지가 손상되어 로드되지 않음, 내용상 headline/summary와 관련이 없어 보임 등.
  - 이상하다고 판단되면 그 이미지는 배경으로 쓰지 않고, Aside MCP(`mcp__aside__repl`)로 이미지 검색 사이트(예: Google 이미지 검색)에 접속해 이 gen의 `headline`/`summary`에서 뽑은 핵심 키워드로 검색한 뒤, 검색 결과 중 고해상도이고 워터마크·과도한 텍스트/UI가 없는 이미지를 하나 골라 2단계 임시 디렉토리에 새로 다운로드해 대체 배경으로 사용한다.
  - `thumbnail_image_url` 이 로컬 절대경로(크롤링 스킬이 소유한 파일)인 경우에도, 디자인이 이상하면 그 원본 파일은 수정·삭제하지 않고 대체 이미지만 새로 받아 이번 발행에 한해 배경으로 쓴다. `gen.thumbnail_image_url` 값 자체는 변경하지 않는다.
  - 적절한 대체 이미지를 찾지 못하면 템플릿 기본 배경을 유지한다.
- **상단 좌측 few.letter 브랜드 배지**: 카드 좌측 상단(캔버스 기준 대략 `left 40px, top 40px`, 1440x1800 기준으로는 비율 환산)에 연두색(`#C1FF72`) 알약(pill) 모양 배지가 있고, 그 위에 **"few.letter"** 텍스트가 굵은 글씨로 표시되어야 한다.
  - 템플릿(`main페이지.html`)에는 이미 배지 배경 + `few.letter` 텍스트가 구현돼 있으니 **문구·색을 임의로 바꾸지 말고 그대로 유지**한다.
  - 이 템플릿을 참고해 직접 HTML을 새로 작성하는 경우에도 반드시 **어두운 색 텍스트(예: `#10210a`)를 밝은 초록 배경 위에** 올려서 가독성을 확보한다. 흰색·연한 색 텍스트를 밝은 초록 배경에 쓰면 안 보이므로 금지.
  - 이 배지 레이어는 배경 이미지·그라데이션 오버레이·다른 텍스트 레이어보다 **항상 위(나중에 그려지는 순서)**에 위치시켜, 다른 레이어에 가려 텍스트가 안 보이는 일이 없게 한다.
- **작은 텍스트(날짜)**: 이 gen의 `created_at` 날짜. 포맷 `YYYY년 M월 D일` (제로패딩 없음, 예: `2026년 8월 30일`).
- **큰 텍스트**: 이 gen의 `headline` 그대로 사용한다. (기존 `주요 ${Category} 소식` 문구는 삭제되었고 category 개념 자체를 더 이상 사용하지 않는다.)
  - headline이 길어 한 줄에 안 들어가면 적절히 개행한다. 단, 위쪽 날짜 텍스트(top≈681px)와 아래쪽 해시태그/로고 영역(top≈916px)에 겹치지 않도록 폰트 크기·줄 수를 조절한다.
- **해시태그(이미지 내 3개)**: 이 gen의 `headline`/`summary` 내용에서 주요 키워드 **3개**를 선정해 작성한다.
  - 각 해시태그는 few.letter 배지와 동일하게 **초록색(`#C1FF72`) 알약(pill) 배경 위에 어두운 텍스트(`#10210a`)**로 표시한다(템플릿에 이미 구현됨 — 임의로 배경을 없애거나 색을 바꾸지 말 것).
- **하단 "넘겨서 자세히보기" 문구 및 스와이프 화살표**: 캐러셀이 아니므로 삭제되었다. (템플릿에서 이미 제거됨 — 새로 채우지 않는다.)

#### PNG 로컬 저장
- 임시 디렉토리를 만든다: `~/Downloads/${현재날짜및시간}/gen-<gen.id>-<YYYYMMDD-HHMMSS>/`
- 생성된 html 완성본을 위 임시 디렉토리에 png, jpg, jpeg 등의 파일로 다운로드 한다.
- 파일명: `main.png` (또는 동일 확장자 규칙을 지키는 다른 이름도 무방).

#### 생성 완료 검증 (업로드 전 필수)
- 임시 디렉토리 안에 카드 파일이 정확히 **1개** 존재하는지 assert. 없거나 렌더 실패면 **이 gen은 업로드·플래그 UPDATE 하지 말고 중단·보고**.
- 파일이 `1440x1800 px` 인지 assert (위 "이미지 규격" 참고).
- 저장된 PNG를 열어(스크린샷 확인) **좌측 상단 배지에 "few.letter" 텍스트가 실제로 눈에 보이는지** 확인한다. 초록 배지만 있고 글씨가 안 보이면(배경과 같은 색 텍스트, 다른 레이어에 가려짐 등) **렌더링 실패로 간주해 재생성**하고, 그래도 안 보이면 업로드하지 말고 중단·보고.

### 3. 캡션(본문 내용) 생성
포맷:
```
{headline}

{summary}

더 많은 글로벌 경제 및 증시 소식과 속보는? @few.ai.letter

#{해시태그1} #{해시태그2} #{해시태그3} #{해시태그4} #{해시태그5}
```
- **1번째 줄**: 이 gen의 `headline` 그대로. (기존 `few letter가 정리한 {M}월 {D}일 {category} 주요소식` 문구는 삭제되었다.)
- 한 줄 띄우고 이 gen의 `summary` 를 넣는다. (headline은 이미지 안에 이미 표시되므로 캡션에서는 summary만 본문으로 사용)
- 여러 gen의 headline을 번호로 나열하던 목록(`1. ... 2. ... 3. ...`)은 더 이상 사용하지 않는다. (게시물 1개 = gen 1건이므로 나열할 대상이 없음)
- summary 다음 한 줄 띄우고 **고정 문구** `더 많은 글로벌 경제 및 증시 소식과 속보는? @few.ai.letter` 를 그대로 넣는다 (변경 없음, 항상 이 문구).
- 그 **고정 문구 뒤에** 한 줄 띄우고 해시태그 5개를 마지막 줄로 넣는다.
- 해시태그는 **정확히 5개**, 모두 이 gen의 headline/summary 내용에서 추출한다. 메인 이미지의 키워드 3개를 그대로 포함하고, 캡션 전용 2개를 추가한다.
- 캡션 어디에도 category(경제/정치/기술 등) 값을 노출하지 않는다.

### 4. 인스타그램 업로드 (Aside MCP)

> ⚠️ 과거 실패 사례: 4:5 카드가 1:1 정사각으로 잘림. 아래 절차를 그대로 따를 것.

1. `mcp__aside__repl` 로 instagram.com 탭을 열거나 attach (`openTab` / `attachActiveBrowserTab`). 로그인 안 되어 있으면 중단하고 사용자에게 로그인 요청.
2. **업로드할 파일**: 2단계에서 만든 `main.png` 1개의 절대경로.
3. 새 게시물 만들기: 좌측 사이드바의 `svg[aria-label="새로운 게시물"]` 클릭 → 서브메뉴("게시물"/"라이브 방송"/"광고")가 뜨면 텍스트가 "게시물"인 링크를 클릭(`a`가 2개 매칭되므로 `nth(1)`, 즉 두 번째가 실제 메뉴 항목) → "새 게시물 만들기" 다이얼로그 오픈.
4. **이미지 업로드**: 다이얼로그 안의 `input[type=file]` (보통 `accept` 에 image 포함) 요소를 찾아, `setInputFiles([파일경로])` 로 파일 1개를 전달한다.
   - ⚠️ Aside REPL 은 `~/Downloads` 등 임의 경로 파일 접근을 막는다. `setInputFiles` 가 "Path escapes session directory" 로 실패하면, 카드 PNG를 `pwd`(REPL 세션 디렉토리) 하위 `tmp/cards/gen-<gen.id>/` 로 복사한 뒤 그 경로로 `setInputFiles` 를 호출한다. 발행 완료 후 이 복사본도 함께 삭제.
   - `setInputFiles` 후 크롭(자르기) 화면으로 진입했는지 확인. 진입하지 않으면 파일 input 을 잘못 잡은 것 → 다이얼로그 재오픈 후 재시도.
5. **비율을 "4:5"로 고정** — 잘림 방지의 핵심. 이 UI는 Playwright의 일반적인 `locator(...).click()` / `:has-text()` 셀렉터로는 신뢰성 있게 조작이 안 된다 (메뉴 항목이 일반 DOM 쿼리로 안 잡히고, 접근성 스냅샷에서만 보임 — 셰도우 DOM/별도 렌더링 레이어로 추정). 아래 **좌표 기반 마우스 클릭** 방식만 안정적으로 동작함이 확인됐다:
   - `svg[aria-label="자르기 선택"]` 의 boundingBox를 구해 그 중심 좌표를 `igPage.mouse.click(x, y)` (Playwright의 실제 마우스 이벤트)로 클릭해 비율 메뉴를 연다.
   - 메뉴가 열리면 **원본 대신 반드시 "4:5" 옵션을 좌표로 클릭**한다. 메뉴는 크기 조정 아이콘 기준 위쪽에 세로로 `원본 → 1:1 → 4:5 → 16:9` 순서로 나타나며, 아이콘 클릭 지점 기준 대략 `x는 아이콘과 동일, y는 원본 항목보다 약 100px 위(= 1:1보다 50px, 원본보다 100px 위)` 에 4:5가 위치한다 (예: 아이콘이 (396,772)면 4:5는 대략 (420,675) 부근 — 실제 좌표는 매번 스크린샷으로 재확인할 것). **"원본"을 클릭하면 미리보기는 잘림 없이 정상으로 보이지만 실제 발행 시 1:1로 잘리는 버그가 있었다 — 반드시 "4:5"를 명시적으로 클릭할 것.**
   - ⚠️ 크롭 미리보기 화면 스크린샷은 실제 선택된 비율과 무관하게 항상 잘림 없이 보이는 것으로 확인됨 (미리보기가 실제 내보내기 비율을 반영하지 않는 듯). **미리보기 스크린샷으로 비율 선택 성공 여부를 판단하지 말 것** — 반드시 10단계처럼 발행 후 실제 게시물을 열어 시각적으로(스크린샷) 확인해야 한다.
   - 이 메뉴는 열렸다가 짧은 시간 내에 자동으로 닫히는 것으로 보이므로, 아이콘 클릭 → 짧은 대기(200~300ms) → 좌표 클릭을 **하나의 코드 실행(같은 툴 호출)** 안에서 연달아 수행할 것. 별도의 툴 호출로 나누면 그 사이에 메뉴가 닫혀 실패한다.
6. **다음 버튼**: 화면 우측 상단의 "다음"은 `aria-label="다음"` 이 아니라 (그 aria-label은 숨겨진 `tabindex="-1"` 더미 버튼에 붙어있음) 실제로는 텍스트 "다음"을 담은 `div[role="button"]` 이다. `document.querySelectorAll('div,span,a,button')` 중 자식 텍스트 노드가 정확히 "다음"인 요소를 찾아 `.click()` 하는 방식으로 클릭한다 (아래 "다음/공유하기 클릭 방법" 참고). 크롭 화면과 편집 화면 각각에서 한 번씩, 총 두 번 클릭해야 캡션 화면에 도달한다.
   - **"다음/공유하기 클릭 방법" (재사용 가능한 헬퍼)**:
     ```js
     function clickByText(text) {
       return igPage.evaluate((t) => {
         const all = Array.from(document.querySelectorAll('div,span,a,button'));
         const match = all.find(el => el.childNodes.length && Array.from(el.childNodes).some(n => n.nodeType===3 && n.textContent.trim()===t));
         if (!match) return 'not found: ' + t;
         match.click();
         return 'clicked: ' + t;
       }, text);
     }
     ```
     "다음", "공유하기" 모두 이 헬퍼로 클릭한다. `button:has-text(...)` 셀렉터나 `[aria-label="다음"]`/`[aria-label="공유하기"]` 는 숨겨진 더미 요소에 걸리거나 매칭이 안 되어 실패한다.
   - **`Escape` 키를 누르지 말 것**: 캡션 입력 중 해시태그 자동완성 드롭다운을 닫으려고 `Escape` 를 누르면 전체 새 게시물 다이얼로그의 "게시물을 삭제하시겠어요?" 확인창이 뜬다 (작성 중인 내용을 버리는 동작으로 처리됨). 자동완성을 닫아야 하면 **`Tab` 키**를 사용할 것.
7. **오디오 추가**:
   - 필터/편집 화면에 '필터' · '조정' 탭과 함께 **'오디오'** 탭(음표 아이콘, `aria-label` 이 "오디오" 류)이 있으면 클릭해 오디오 선택 화면으로 진입한다.
   - 오디오 선택 화면 상단 탭에서 **'저장됨'**(Saved)을 클릭한다.
   - '저장됨' 목록에 있는 오디오 중 **아무거나 하나(예: 첫 번째 항목)** 를 클릭해 선택한다. 특정 곡을 지정할 필요 없이 매번 임의로 하나 고르면 된다.
   - 트리밍(재생 구간) 화면이 뜨면 기본 구간 그대로 우측 상단 **완료**(또는 이에 해당하는 확인 버튼)를 눌러 확정한다.
   - '오디오' 탭 자체가 안 보이거나 '저장됨' 목록이 비어 있으면 **오디오 추가는 건너뛴다** — 이는 실패로 간주하지 않고 그대로 다음 단계로 진행.
   - 다시 **다음** 클릭해 캡션 화면으로 이동.
8. 캡션 입력란(`textarea` 또는 `[contenteditable]`)에 3단계 캡션을 입력한다.
   - **입력 즉시 값 검증(필수)**: 입력 후 바로 해당 요소의 `textContent`/`value`(또는 `innerText`)를 읽어, 3단계에서 만든 캡션의 첫 줄(headline)과 마지막 줄 해시태그 5개가 실제로 그 안에 들어있는지 확인한다. 비어있거나 일부만 들어갔으면 **공유하기로 넘어가지 말고** 입력란을 다시 클릭/포커스한 뒤 재입력을 시도한다(최대 2회). 재시도해도 비어있으면 이 gen은 업로드를 중단하고 사용자에게 보고(플래그 UPDATE 금지).
9. **공유하기** 클릭 (위 헬퍼 사용). 업로드 진행 표시가 사라지고 다이얼로그가 닫힐 때까지 대기.
10. **발행 후 검증 (실패 시 6단계 플래그 UPDATE 금지)**:
    - 프로필(`https://www.instagram.com/<계정>/`)에서 방금 게시물을 열거나, 게시 완료 후 노출되는 게시물 URL로 이동.
    - 단일 이미지 게시물이므로 캐러셀 "다음"(Next) 버튼/슬라이드 인디케이터가 **없어야** 정상.
    - 비율 확인: **`page.screenshot()` 로 게시물 페이지를 실제로 캡처해 시각적으로** 이미지가 세로로 긴 4:5 형태인지 확인한다. (`document.querySelectorAll('img')` 로 `naturalWidth/naturalHeight` 를 읽는 방식은 신뢰할 수 없음 — 실제 게시물과 무관한 `1440x1440` 빈 alt 이미지가 항상 함께 잡혀 혼동을 준다.) 정사각형으로 보이면 잘린 것 → 실패로 간주.
    - **캡션 존재 확인(필수)**: 게시물 상세 화면에서 캡션(본문) 텍스트가 표시되는지 확인한다 — 화면 텍스트를 읽거나(`page.screenshot()` 육안 확인, 또는 캡션이 렌더링되는 DOM 요소의 텍스트) 3단계 캡션의 headline 문구가 실제로 노출되어 있는지 본다. 캡션 영역이 비어있거나 headline이 보이지 않으면 **캡션 누락으로 간주해 실패 처리**.
    - 위 검증 중 하나라도 실패하면 이 gen은 **플래그 UPDATE / 임시 디렉토리 삭제를 하지 말고** 사용자에게 보고.

### 5. 업로드한 게시물을 스토리로 공유 (Aside MCP)
> 4단계 발행 후 검증까지 통과한 게시물에 대해서만 수행. 검증 실패 시 이 단계는 건너뛴다.

1. 4-9에서 확인한 방금 게시한 게시물 페이지로 이동(또는 이미 열려 있는 상태 유지).
2. 게시물 하단 액션 영역의 **공유하기(종이비행기/Share)** 아이콘을 클릭.
3. 열리는 공유 다이얼로그에서 **"스토리에 추가"** (Add post to your story) 옵션을 선택.
   - 옵션이 안 보이면 게시물 우측 상단 **더보기(⋯)** 메뉴 → "스토리에 게시물 추가" 류의 항목을 대신 사용.
4. 스토리 편집 화면(게시물이 스티커 형태로 얹힌 미리보기)이 뜨면 별도 수정 없이 그대로 우측 하단 **"내 스토리에 공유"**(Share to Story) 버튼을 클릭.
5. **공유 완료 검증**: 다이얼로그가 닫히고 업로드 진행 표시가 사라질 때까지 대기 후, 내 프로필 좌측 상단 스토리 링(아바타 원형 테두리)이 새로 생겼는지, 또는 스토리를 열어 방금 발행한 게시물이 스티커로 포함돼 있는지 확인.
   - 실패(다이얼로그가 안 닫히거나 스토리 링이 안 보임) 시 재시도 1회. 그래도 실패하면 **게시물 발행 자체는 성공한 것으로 간주**하고(6단계 플래그 UPDATE는 정상 진행), 스토리 공유만 실패했다고 사용자에게 보고.

### 6. 발행 플래그 마킹 (MySQL MCP)
이 gen의 게시가 **성공한 경우에만** (= 4-9 발행 후 검증까지 통과. 5단계 스토리 공유 성공 여부는 무관):
```sql
UPDATE gen SET published_via_skills_yn = 'Y' WHERE id = <이 gen id>;
```

### 7. 네이버 블로그 발행 (인스타그램 발행 완료 후)
> 6단계 플래그 마킹까지 성공한 gen에 대해서만 수행한다. 인스타그램 발행이 실패해 6단계를 건너뛴 gen은 이 단계도 건너뛴다. 8단계(임시 디렉토리 삭제)보다 반드시 먼저 수행해야 한다 — 2단계에서 만든 카드 이미지 파일을 그대로 사용하기 때문.

1. `mcp__aside__repl` 로 네이버 블로그(사용자의 블로그, blog.naver.com) 탭을 열거나 attach. 로그인이 안 되어 있으면 이 gen의 블로그 발행만 건너뛰고(인스타그램 발행·플래그는 그대로 유지) 사용자에게 로그인을 요청한다.
2. 새 글쓰기 화면으로 진입한다. 정확한 버튼/셀렉터는 매번 접근성 스냅샷(snapshot)으로 확인해 클릭한다 (Naver SmartEditor는 셰도우 DOM/iframe 구조라 고정 셀렉터를 미리 단정하지 않는다).
3. **카테고리**를 **"경제"**로 지정한다. 글쓰기 화면 상단(또는 발행 설정 패널)의 카테고리 선택 드롭다운에서 "경제" 항목을 선택한다. "경제" 카테고리가 없으면 새로 만들지 말고 이 사실을 사용자에게 보고한다.
4. **제목**: 이 gen의 `headline` 그대로 입력한다. (다른 문구 추가 금지)
5. **본문**:
   1. 먼저 2단계에서 만든 카드 이미지(`main.png`, 절대경로)를 본문 최상단에 삽입한다. 에디터의 사진 첨부 기능으로 로컬 파일을 업로드한다 (파일 선택 `input[type=file]` 에 `setInputFiles` 또는 동일한 사진 삽입 버튼 클릭 후 파일 다이얼로그 처리).
   2. 이미지 삽입 직후, 그 아래에 **3단계에서 만든 인스타그램 캡션을 그대로** 본문 텍스트로 입력한다 (headline/summary/고정 문구/해시태그 5개 전부 포함, 캡션과 완전히 동일한 내용 — 별도로 다시 작성하지 않는다).
6. **발행**: 공개 설정으로 발행한다 (비공개/임시저장으로 남기지 않는다). 발행 옵션 팝업이 뜨면 카테고리가 4번에서 지정한 "경제"로 유지되는지 다시 한번 확인 후 발행을 확정한다.
7. **발행 검증**: 발행 후 이동되는 게시글 URL(또는 블로그 글 목록에서 방금 글)을 열어 제목이 headline과 일치하는지, 이미지가 정상 노출되는지, 본문에 캡션 텍스트가 들어갔는지 확인한다.
8. 검증 실패 시 이 gen의 네이버 블로그 발행만 실패로 보고한다 — 이미 완료된 인스타그램 발행·6단계 플래그는 되돌리지 않는다.

### 8. 임시 디렉토리 삭제
6단계 플래그 UPDATE와 7단계 네이버 블로그 발행(성공이든 보고된 실패든 시도 자체)까지 끝났으면, 2단계에서 만든 해당 gen의 임시 디렉토리(`~/Downloads/${현재날짜및시간}/gen-<gen.id>-<YYYYMMDD-HHMMSS>/`)를 `rm -rf` 로 삭제.

## 주의사항
- **gen 1건당 게시물 1개, 이미지 1장(단일 이미지 게시물, 캐러셀 아님)**. 여러 건이면 2~7단계를 각 gen마다 반복.
- category(경제/정치/기술 등) 개념은 이미지·캡션 어디에도 사용하지 않는다. (조회 시 `contents_type` 필터는 유지하되 `category` 컬럼/값은 사용하지 않음)
- 특정 단계 실패 시 그 gen은 **플래그 UPDATE / 임시 디렉토리 삭제를 하지 말고** 실패 사유를 사용자에게 보고. 다른 gen은 계속 진행.
- 날짜 포맷은 항상 `YYYY년 M월 D일` (월·일 제로패딩 없음).
- "어제부터"는 `created_at >= CURDATE() - INTERVAL 1 DAY`.
- 배경 이미지는 카드뉴스 이미지 전체가 채워지도록 적절하게 위치해야 함.
- 이미지 다운로드: thumbnail_image_url이 원격 URL이면 그 url에 Aside를 통해 접속하고 이미지를 로컬에 다운로드해서 사용. **이미 로컬 절대경로**라면 다운로드 없이 그 파일을 그대로 사용한다 (investing-dot-com-crawling 스킬로 생성된 contents_type 4/5 건이 이 경우에 해당).
- html 템플릿 기반으로 이미지 생성시 headline은 적절한 개행을 하고, 길이가 길 경우 템플릿에 명시된 줄보다 더 개행이 들어가도 됨. 다만 headline이 위쪽 날짜 텍스트나 아래쪽 해시태그/로고 영역과 겹쳐 보이지 않도록 영역·폰트 크기를 적절히 조절해야 함.
- **이미지 크기는 항상 `1440 x 1800 px` (4:5) 고정.**
- 인스타 업로드 시 크롭 화면에서 **반드시 "원본"(또는 4:5) 비율 선택**. 기본값 1:1 로 진행하면 카드 상·하단(날짜줄, 해시태그)이 잘린다.
- 업로드는 `setInputFiles` 에 파일 경로 1개를 전달.
- 편집 화면의 **오디오 추가**는 '저장됨' 탭에서 임의의 1곡을 선택(특정 곡 지정 없음). '오디오' 탭이나 '저장됨' 목록이 없으면 건너뛴다 — 실패로 간주하지 않음.
- 발행 직후 게시물을 다시 열어 **단일 이미지(캐러셀 아님)**, **비율 4:5**, **캡션이 실제로 붙어있는지**를 모두 검증. 캡션은 이미지 위 텍스트로는 대체되지 않으므로 반드시 게시물 본문 캡션 영역에 headline/summary/해시태그가 노출돼야 정상이다. 실패하면 플래그 UPDATE·임시 디렉토리 삭제를 하지 말고 보고.
- 캡션 입력(8단계)은 입력 직후 실제 값이 들어갔는지 DOM에서 재확인하고, 비어있으면 재입력을 시도한다 — 조용히 실패한 채로 공유하기로 넘어가지 않는다.
- 인스타그램 발행(6단계 플래그 마킹)이 성공한 gen은 반드시 7단계에서 네이버 블로그 "경제" 카테고리에도 발행한다. 제목=headline, 본문=카드 이미지+3단계 캡션 그대로. 이 단계는 8단계(임시 디렉토리 삭제) 이전에 끝내야 카드 이미지 파일을 재사용할 수 있다.
- 네이버 블로그 발행이 실패해도 이미 완료된 인스타그램 발행·플래그는 되돌리지 않는다 (블로그 발행 실패만 별도로 보고).
